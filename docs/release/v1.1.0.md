# bloom-lib v1.1.0

A fix release from an independent review. Hashing is now the same on every
target, deserialization validates its input, oversized constructor parameters
return errors instead of aborting, and a keyed hasher is available for untrusted
input. There is no breaking API change and the MSRV stays at Rust 1.75.

## Compatibility with stored state

Callers such as lsm-db store serialized filters on disk and query them later, so
compatibility was the first constraint.

- On x86_64 and aarch64, hash values and serialized bytes are exactly what 1.0.0
  produced. `tests/golden.rs` pins hash values for byte slices of several
  lengths, strings, every integer type, tuples and `Option`, plus the full
  serialized form of every structure, all recorded from 1.0.0 on x86_64. The
  same tests pass on 1.1.0 on x86_64, on `i686-pc-windows-msvc` locally, and in
  CI on `i686-unknown-linux-gnu` and big-endian `s390x-unknown-linux-gnu`.
- On 32-bit and big-endian targets the hash values change, to match x86_64.
  State that 1.0.0 wrote on those targets must be rebuilt. State written on
  x86_64 or aarch64 can now be queried there, which was not true before.
- From 1.1.0, hash values and the serialized form are held fixed for the rest
  of 1.x.

## Portable hashing

1.0.0 used the standard library's default `Hasher` integer methods, which feed
native-endian bytes and a native-width `usize`. The length prefix of a `[u8]` or
`str` key was 4 bytes on 32-bit targets, and integer keys were byte-swapped on
big-endian targets, so a filter written on x86_64 reported its keys as absent on
i686, armv7, wasm32 or s390x. Both hashers now feed integers in little-endian
order and widen `usize` and `isize` to 64 bits. On 64-bit little-endian targets
that is the same byte stream as before.

One limit remains, from the standard library: a slice or `Vec` of multi-byte
integers (`[u32]`, `Vec<u64>`) is hashed as one block of native-endian bytes.
Use `[u8]`, `str` or single integers as keys for state that moves between
machines of different byte order.

## Validated deserialization

Every structure now has its own `Deserialize` that decodes the same format as
before and then checks it: word count against bit count for Bloom filters,
`width * depth` against the counters for Count-Min, `2^precision` registers and
the largest possible rank for HyperLogLog, bucket mask, slot count, victim and
length for Cuckoo filters, a non-empty MinHash signature, and `k` for Top-K. The
Bloom hash count is capped at 2,048. Inconsistent input returns an error; in
1.0.0 it produced a structure that panicked, looped for as long as the input
said, or reported every item as present.

## Keyed hashing

`hash::KeyedHashBuilder` (SipHash-2-4 with a 128-bit secret key) is the hasher
to use when an adversary chooses the items. The default hasher's seed is public
and its collisions can be computed directly: the review built 1,000 colliding
16-byte keys without any search and filled a Cuckoo filter sized for a million
items with 9 of them. With a keyed hasher the same keys behave like any others.

Serialized state never includes the hasher, so a keyed structure is restored by
deserializing it with the default hasher type and calling
`replace_hasher(KeyedHashBuilder::new(key))`. `KeyedHashBuilder` has no
`Default`, so it cannot be deserialized with a made-up key by accident. Do not
persist a structure built with `RandomState`: its `Default` draws a new key, and
the restored structure reports almost every stored item absent.

## Constructor limits

Every constructor computes sizes with checked arithmetic and allocates with
`try_reserve_exact`. Sizes that overflow or cannot be allocated return
`Error::InvalidParameter` instead of aborting the process or panicking.
`with_dimensions` also rejects a Bloom hash count above 2,048.

## Upgrading

Change the dependency to `bloom-lib = "1.1"`. No code changes are needed. If you
deserialize state from outside your trust boundary, expect errors for
inconsistent input where 1.0.0 accepted it. If you persisted filters on a 32-bit
or big-endian target, rebuild them.
